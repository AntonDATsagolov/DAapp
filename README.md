# DAapp — цифровой Шиели (Шиелі)

DAapp — единая экосистема для **посёлка Шиели, Шиелийский район, Кызылординская область, Казахстан**. Три мобильных веб-интерфейса используют один проект Supabase.

**Главный адрес:** https://antondatsagolov.github.io/DAapp/

## Интерфейсы

- [Для жителей и гостей](https://antondatsagolov.github.io/DAapp/client-app/) — интерактивная карта Шиели, категории, геолокация по разрешению, переход по координатам и профиль.
- [Для предпринимателей](https://antondatsagolov.github.io/DAapp/business-app/) — подача заявки на организацию Шиели и просмотр собственных статусов; публикация только после модерации.
- [Для водителей](https://antondatsagolov.github.io/DAapp/driver-app/) — мобильный кабинет, приватная анкета водителя, проверка администратором и выход на линию. Заказы пассажиров **пока не подключены**. Для сохранения нужен [SQL 007 и настройка](driver-app/STEP_11_DRIVER.md).
- [Модерация](https://antondatsagolov.github.io/DAapp/admin-app/) — отдельная панель для проверенного администратора: очередь заявок, одобрение с проверенными координатами, отклонение и журнал решений в базе. Нужна миграция SQL 006 и ручное назначение администратора. В панели есть безопасная кнопка проверки пяти компонентов без записи в базу. [Инструкция](admin-app/STEP_09_ADMIN.md).
- `shared/supabase.js` — общий публичный клиент Supabase.
- `supabase/migrations/` — SQL для настройки базы (выполняется администратором отдельно).

## Карта жителя: полноэкранный и обычный виды

Карта по умолчанию разворачивается на доступную площадь экрана. Категории
«Магазины», «Кафе», «Красота», «Гостиницы», «Такси» доступны прямо над картой.
Кнопка **«Обычный вид»** возвращает прежнюю компоновку с нижним каталогом;
**«На весь экран»** — обратно. Предпочтение вида сохраняется локально на
устройстве; после смены вида Leaflet пересчитывает размеры без перезагрузки.
На полноэкранной карте кнопка **«Список мест»** разворачивает результаты
выбранной категории, в том числе сообщение об отсутствии опубликованных мест.
Карта и фильтры доступны без авторизации.

**Такси — пока только категория опубликованных организаций:** этот фильтр читает
`map_places.category='taxi'`, но **не** таблицу индивидуальных водителей
`driver_registrations`. Поэтому отсутствие служб такси на карте не означает,
что зарегистрированных водителей нет. Житель может открыть категорию без них,
но приём заказов такси, подбор доступного водителя и карта их текущего положения
ещё **не реализованы**. Интерфейс объясняет это без фиктивных поездок или
несуществующих организаций.

## Начальная карта

При открытии карта показывает Шиели около координат **44.17603, 66.74096** (точка населённого пункта OpenStreetMap), масштаб 13. Это **ориентир населённого пункта**, а не точное местоположение пользователя. Для показа текущей геопозиции нужна кнопка «Где я?» и разрешение браузера. Список и маркеры публикуемых организаций читаются из отдельной таблицы `public.map_places` после ручного выполнения SQL-миграции 004. Если таблица ещё не создана или не содержит проверенных точек, карта остаётся доступной без них. Инструкция: [шаг 7 — публичный каталог](client-app/STEP_07_PUBLIC_CATALOG.md). Подробности: [Шаг 6 — карта](client-app/STEP_06_MAP.md).

## Один адрес, один аккаунт и последний режим

**Единая ссылка для всех пользователей: https://antondatsagolov.github.io/DAapp/**

После авторизации DAapp открывает последний доступный режим — жителя, предпринимателя или водителя. Предпочтение сохраняется в Supabase и восстанавливается после перезапуска браузера и при смене устройства. В настройках каждого модуля есть **«Сменить режим»**. Доступные режимы определяются сервером: бизнес — после одобренной заявки организации, водитель — после подтверждения анкеты. Для получения нового статуса есть отдельная ссылка подачи заявки. Выбор роли при регистрации сам по себе не даёт права выполнять заказы.

Эта маршрутизация требует миграции **SQL 011** после 001–010. Без её установки страница входа будет работать как обычный личный кабинет, но автоматическое переключение и запоминание режима недоступны. Технические ссылки отдельных модулей остаются доступны, однако не дают привилегий без серверного разрешения.

[Шаг 15: единый вход и сохранение режима](account-app/STEP_15_UNIFIED_ENTRY.md).

## Регистрация, сценарии и центр управления

**Форма регистрации и настройки профиля:** https://antondatsagolov.github.io/DAapp/account-app/?manage=1

Новый человек заполняет логин, пароль, e-mail, контактный номер, возраст, фото (после подтверждения почты), выбирает **житель/гость** и первичное направление: **обычные городские сервисы / предпринимательство / водитель**. После однократного подтверждения e-mail обычный доступ автоматически открывается по новой миграции **SQL 010**. Не нужно одобрять вручную каждого жителя. Парольный вход по e-mail доступен без повторного получения ссылок; отдельный логин вместо e-mail требует развёрнутой Edge Function.

Предприниматель и водитель получают **тот же базовый доступ**, но дополнительные права только после отдельной проверки своих заявок: `business-app` и `driver-app`. Фото транспорта, год выпуска, каталог товаров, реальные заказы пассажиров и покупателей пока требуют следующих этапов разработки. **Не обещайте эти функции конечным пользователям как работающие.**

**Админ/архитектор:** https://antondatsagolov.github.io/DAapp/admin-app/ — обычный e-mail + пароль, при необходимости однократный Magic Link для установки пароля; серверная статистика, реестр пользователей, статусы, заявки организаций и водителей, диагностика. Архитектор с отдельным, доверенным SQL-разрешением может управлять автоматическим доступом, справочником, блокировками неадминских аккаунтов и аудитом.

**Справочник контактов:** https://antondatsagolov.github.io/DAapp/directory-app/ — номер виден другим одобренным пользователям только по согласию взрослого владельца. SMS пока не применяется.

**Для реального запуска** необходимы SQL 009, затем **SQL 010 и 011**, Confirm Email и корректные Redirect URLs в Supabase. Функция логина по имени пользователя требует отдельного развёртывания. Наличие страниц GitHub Pages не означает, что SQL и Auth-настройки уже выполнены.

[Инструкция по регистрации и панели архитектора](admin-app/STEP_14_CONTROL_CENTER.md).

## Запуск и тесты

GitHub Pages автоматически публикует обновления основной ветки `main`; localhost не требуется. Для локальной разработки: `python3 -m http.server 8000` из корня, затем `http://localhost:8000/client-app/`.

Тесты: `node --test tests/smoke.test.mjs`. Они автоматически проверяются в GitHub Actions.

## Безопасность и текущие ограничения

В репозиторий разрешено записывать только Supabase **publishable key**, никогда `sb_secret_*` или `service_role`. Доступ к таблицам должен ограничиваться RLS. Карту можно просматривать без входа, а настройки профиля требуют Supabase Auth. Полноценное управление каталогом предпринимателя, редактирование опубликованных организаций, бизнес-заказы, реальные заявки на такси и доставку, офлайн-кэш и устанавливаемые PWA ещё не реализованы. Для приёма заявок требуется ручная миграция `005_shieli_place_submissions.sql` и разрешённый redirect URL бизнес-приложения. [Шаг 8 — заявки](business-app/STEP_08_SUBMISSIONS.md).
