# DAapp — Шаг 11: приложение для водителей Шиели

## Что работает

Ссылка: https://antondatsagolov.github.io/DAapp/driver-app/

- На первом экране видны направления «Такси» и «Доставка», статус линии и кабинет.
- Авторизация через Supabase Email Magic Link (общий аккаунт DAapp).
- Водитель один раз отправляет анкету: ФИО, телефон, тип транспорта, модель и госномер.
- Заявка приватна и получает статус **«На проверке»**.
- В существующей административной панели появляется очередь водителей с кнопками **«Одобрить»** / **«Отклонить»**.
- При одобрении водителю становится доступно переключение **«На линии» / «Завершить смену»**. Состояние сохраняется в Supabase, а не только в браузере.
- У заявки «Отклонена» выход на линию заблокирован.
- Раздел «Заказы» честно говорит, что **реальные заявки пассажиров и маршрутизация ещё не реализованы**. Ни одна поездка не создаётся автоматически.

## Одна новая миграция: SQL 007

В Supabase проекте DAapp сначала должны быть выполнены предыдущие миграции, включая 006 (`daapp_admins`). **Не запускайте их повторно.**

Откройте [SQL 007](../supabase/migrations/007_shieli_driver_onboarding.sql) — весь файл, через Raw, скопируйте и выполните в Supabase SQL Editor как администратор. Если таблица `driver_registrations` уже существует, миграция намеренно остановится, чтобы не перезаписать её.

Эта миграция не изменяет существующие `profiles`, `businesses`, `place_submissions` и `map_places`.

В Supabase **Authentication → URL Configuration → Redirect URLs** добавьте:

`https://antondatsagolov.github.io/DAapp/driver-app/`

Другие Redirect URLs (для карты, бизнеса и администратора) оставьте без изменений.

## Первый проход

1. Откройте приложение водителя, войдите по e-mail.
2. Заполните анкету **реальными данными** для тестового водителя.
3. Откройте https://antondatsagolov.github.io/DAapp/admin-app/ под доверенным администратором, найдите раздел **«Заявки водителей Шиели»**, обновите очередь.
4. Лично проверьте человека, удостоверение, транспорт, право выполнять перевозки. Поставьте отметку и только после проверки нажмите «Одобрить» (или «Отклонить»).
5. На странице водителя нажмите «Обновить анкету». При одобрении должны появиться кнопки смены. Проверьте переход «На линии» и «Завершить смену».

**Важно:** Отметка «На линии» пока **не означает получение заказов** — сервисы пассажирских заявок и доставки ещё не подключены. Приложение не собирает и не публикует точную геолокацию водителей.

## Безопасность

- Публичная таблица `driver_registrations` имеет RLS: водитель видит только **свою** запись.
- Браузерная вставка ограничена полями анкеты. `user_id` берётся из проверенной Supabase-сессии, а `review_status=pending` и `is_online=false` — из SQL DEFAULT.
- Клиент не может напрямую менять статус проверки, назначать себе роль `driver`, читать чужие телефоны или номера автомобиля и включать линию, пока не одобрен администратором.
- Одобрение/отклонение доступны только проверенным членам `daapp_admins`, через серверную функцию `daapp_admin_review_driver`.
- Переключение линии разрешено функцией `daapp_driver_set_online` только одобренному пользователю для собственной записи.
- В клиентском коде нет Supabase secret/service_role.
- Администратор обязан проверять реального водителя и его документы до одобрения; программная проверка этих документов пока не реализована.

## Ограничения

Регистрация пока однократная; редактирование анкеты, повторная подача отклонённой анкеты, журнал решений по водителям, тарифы, заявка пассажира, матчинг и расчёт поездки запланированы отдельно. Нельзя выдавать это за уже действующее такси.
