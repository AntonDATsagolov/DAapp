# DAapp — Шаг 8: заявки от предпринимателей Шиели

## Как работает

1. Предприниматель открывает https://antondatsagolov.github.io/DAapp/business-app/.
2. Входит по magic-link на e-mail (если уже вошёл в DAapp для жителей, сессия общая на этом домене).
3. Заполняет название, категорию, адрес, контактный телефон и **по желанию** точные координаты.
4. Заявка сохраняется в **private** `public.place_submissions` со статусом `pending`.
5. Предприниматель видит только **свои** заявки и их статусы: `pending`, `approved` или `rejected`.
6. **Никакая заявка не публикуется на карте автоматически.** Администратор проверяет сведения и вручную вносит подтверждённую запись в `map_places`.

Аккаунту достаточно быть авторизованным. Не требуется назначать непроверенным пользователям роль `business_owner`: заявка **не является** доказательством владения точкой.

## Настройка — один раз в Supabase

**Перед запуском:** убедиться, что `public.place_submissions` ещё не существует, и проверить, что подключён правильный проект Supabase. Ничего удалять не нужно.

Откройте Supabase Dashboard → SQL Editor и выполните файл:

`supabase/migrations/005_shieli_place_submissions.sql`

Скрипт **останавливается**, если таблица уже существует. Имеющиеся `profiles`, `businesses`, `map_places` и пользователи не изменяются.

Также откройте Supabase → Authentication → URL Configuration и внесите в **Redirect URLs** точный адрес:

`https://antondatsagolov.github.io/DAapp/business-app/`

Проверьте, что провайдер Email включён и отправка magic-link не заблокирована лимитами почты.

## Права и защита данных

- Анонимный пользователь не может отправлять или читать заявки.
- RLS на `place_submissions`: только собственные заявки по `auth.uid()`.
- Браузерный клиент может передавать только `name`, `category`, `address`, `contact_phone`, `latitude`, `longitude`.
- `applicant_id` автоматически определяется по авторизованной Supabase-сессии; `status` по умолчанию `pending`.
- Пользователь не может через публичный API менять статус, ID заявителя, удалять заявку или переносить её в `map_places`.
- Телефон в заявке **не публикуется**; администрация может согласовать отдельный публичный номер организации перед добавлением на карту.
- Координаты необязательны. Если они введены, проверяется приблизительный охват Шиели. Нельзя автоматически считать такую точку достоверной.
- Новые правила не ослабляют RLS уже существующих таблиц.

**Ограничение:** нет серверного антиспама и админ-панели модерации, пока только ручная проверка доверенным администратором через SQL Editor. Перед публичным масштабированием понадобятся лимиты запросов, защита от спама и правила обработки контактов.

## Проверка заявок администратором

В **SQL Editor**, с доверенными административными правами (не в браузерном коде DAapp), можно просматривать очередь:

```sql
select id, name, category, address, contact_phone,
       latitude, longitude, status, created_at
from public.place_submissions
where status = 'pending'
order by created_at asc
limit 50;
```

Проверяйте право заявителя представлять организацию и корректность названия, адреса, координат. **Не копируйте данные в публичный каталог автоматически.**

После подтверждения: вручную создайте запись в `public.map_places` (миграция 004), сначала с `is_published=false`, укажите проверенные координаты, затем явно переведите её в опубликованное состояние. Только после этого можно обновить статус **конкретной** заявки по её UUID:

```sql
-- Замените пример UUID на UUID конкретной проверенной заявки.
update public.place_submissions
set status = 'approved'
where id = '00000000-0000-4000-8000-000000000000'
  and status = 'pending';
```

При отклонении одной заявки администратор может выставить `rejected`. В текущей схеме заметки о причинах и связь `place_submissions → map_places` **ещё не реализованы**.

## Важное предупреждение

GitHub Pages публикует HTML/JS, **но не запускает SQL-миграции в базе**. Если SQL 005 не применён, пользователь увидит сообщение о том, что приём заявок не подключён. Настройки SQL 003 (восстановление профилей) и 004 (публичные точки) независимы и устанавливаются отдельно.
